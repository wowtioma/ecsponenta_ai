Основа: сохранённый HTML страницы + 2 скриншота (hero, «Принцип работы») + логотип-щит.
**Что точно (из HTML):** структура, классы, тексты, порядок блоков, подключённые библиотеки, анимации, шрифт, акцентный оранжевый `#FF730F`.
**Что приблизительно (по скриншотам, помечено «≈»):** остальные цвета, размеры, отступы, радиусы. Файл `main.css` в сохранённой странице не был приложен, поэтому эти значения нужно сверить в DevTools (Elements → Computed) или прислать `main.css`, и я заменю «≈» на точные.

## 1. Общая концепция

- Тематика: B2B, информационная безопасность, аппаратно-программное решение (устройство 1U).
- Тип: одностраничный лендинг (one-page) с якорной навигацией + отдельные страницы `/where_to_buy`, `/policy`, `/policy_cookie`.
- Стиль: светлый, «технологичный», много воздуха, крупная типографика в UPPERCASE для кнопок и меню, светлые заголовки, один яркий акцент (оранжевый) + холодная бирюзово-синяя гамма для технических акцентов.
- Настроение: строгое, надёжное, без декоративных излишеств. Фоны светло-серые/белые, фотография устройства как главный визуал.
- Нумерация секций в формате `01/07 … 07/07` (фирменный элемент).
- Язык: русский (`<html lang="ru">`).

### 5.3 «Ключевые возможности» `.features` — `02/07`
Сетка 4 карточки (`features__item`), анимация появления scale 0.5 → 1 + fade (`show.item`). В карточке: иконка 40×40 → H3 → текст.
1. **Изоляция на физическом уровне** (иконка `branch`). Архитектура и технологии решения обеспечивают автоматизированную контролируемую передачу данных в режиме «точка-точка» как в одну, так и в обе стороны по протоколам TCP и UDP без прямой связности узлов.
2. **Разграничение зон ответственности** (`users`). Встречный контроль, реализованный через управление двумя ответственными для подтверждения прохождения данных. Несогласованные с обеих сторон правила игнорируются.
3. **Проверка файлов перед передачей** (`scan`). Проверка размера и маски, а также целостности передаваемых объектов. Имеет встроенные механизмы дополнительной верификации объектов во внешних системах средствами ICAP-протокола.
4. **Физический контроль передачи** (`key`). Физическая блокировка передачи «пусковыми» ключами и возможность запрета удалённого управления с доступом к конфигурированию только через консоль RS-232.

## 7. Анимации (GSAP + ScrollTrigger)

Начальные состояния заданы inline-стилями, срабатывают при входе блока во viewport (`start ≈ top 80%`), `duration ≈ 0.6–0.8s`, `ease: power2.out`.

| Атрибут | Эффект |
|---|---|
| `intro.item` | поочерёдное появление элементов hero |
| `show.text` / `*.text` | из `x: −100`, `opacity 0` → норма |
| `show.item` | из `scale: 0.5`, `opacity 0` → норма (карточки features) |
| `show.card` | из `y: 70`, `opacity 0` → норма (карточки слайдера) |
| `show.block` | из `x: −100` (сценарии) |
| `show.col` | из `scale: 0.5` (интеграции) |
| `show.element.left` / `.right` | из `x: ∓100` (статистика «О компании») |
| `contacts.item` | из `scale: 0.5` |

Hover-состояния: кнопки (смена заливки), логотипы интеграций (серый → цветной), круглые стрелки (лёгкое увеличение). Модалки: fade-in + небольшой scale.
Учесть `prefers-reduced-motion` (отключать анимации).

## 8. Адаптивность

- ≥1440: как описано выше.
- 1024–1439: меню может переноситься, H2 ≈ 56px, features 2×2, integration 3 → 2+1.
- 768–1023: бургер-меню, слайдер principles — 1 карточка на экране, scenarios: текст над иллюстрацией, about: статистика в 1 колонку.
- ≤767: H1 ≈ 24px, wordmark на всю ширину, кнопки на всю ширину, H2 ≈ 36–40px, секции padding ≈ 50–60px, карта на всю ширину высотой ≈ 300px.
- Все изображения `loading="lazy"`, кроме hero (`intro-bg.jpg`, `loader.webp`); указывать `width/height` для исключения CLS.
