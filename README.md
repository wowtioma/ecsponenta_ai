# Экспонента · Синоникс

Ветка `Integration` объединяет чат, базу знаний, ядро расчёта и редактор draw.io. Ядро принимает структурированное описание обмена между двумя сетями, рекомендует размещение межсетевого экрана и «Синоникса», рассчитывает правила и формирует уточняющие вопросы. Расчёт работает локально и даёт одинаковый результат для одинакового входа.

## Что реализовано

- **Состояние сессии.** `Session` хранит сети, потоки, явно согласованные допущения и ответы на уточнения. Неизвестные параметры попадают в `unknowns`, согласованные решения — в `assumptions`.
- **Размещение.** Рекомендуемая цепочка проходит от открытой сети через МЭ и «Синоникс» к закрытой сети. Узел А обращён к открытой стороне, Узел В — к закрытой. USB подключается к Узлу А и на диаграмме проходит мимо МЭ.
- **Расчёт данных.** Потоки с общим получателем, портом и протоколом могут использовать одно правило. MQTT, Modbus TCP и МЭК‑104 требуют двунаправленного правила. NTP рассчитывается как одно однонаправленное правило и выгружается как UDP. При превышении 256 правил ядро возвращает ограничение и сохраняет полный расчёт.
- **Расчёт файловых потоков.** Ядро учитывает проверки на каждой стороне, видимость принятых файлов и совместимость настроек PULL/PUSH. В счётчике файловых пользователей один человек учитывается один раз по идентификатору, каждое правило с PULL добавляет одного технического пользователя, PUSH дополнительных пользователей не добавляет.
- **Уточнения и выгрузка.** Вопросы содержат варианты «Не знаю» и «Другое». Служебный результат версии `1.1` содержит размещение, правила, счётчики и статус `needs_clarification`, `preliminary`, `completed` или `unsupported`.

## Общая локальная сборка A, B и C

Для локального запуска нужны Python 3.10+, Node.js и ключ Groq. Создайте в корне проекта файл `.env`.

```dotenv
LLM_PROVIDER=groq
GROQ_MODEL=openai/gpt-oss-20b
GROQ_API_KEY=<ваш ключ>
```

Первый PowerShell запускает API.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe integration_test_server.py
```

База знаний находится в `synonyx_base/`. Для другого комплекта задайте `SYNONYX_BASE_DIR` или `SYNONYX_CASE_ZIP`. Для тестов ядра и сервера выполните `python -m unittest discover` из корня проекта.

Во втором PowerShell запустите интерфейс из корня той же копии:

```powershell
cd frontend
npm.cmd ci
$env:VITE_USE_MOCK = 'false'
npm.cmd run dev
```

Откройте адрес Vite и отправьте полное описание F02 или вопрос Q01.
Ядро рассчитывает правила и формирует карточки уточнений с вариантами ответов.
Groq составляет сообщение в чате по рассчитанному результату или проверенному
исходу правки. Этот вызов записывается в журнал с назначением `reply_wording`.
При сбое модели сервер показывает свой ответ по тому же результату.
`SYNONYX_LLM_WORDING=0` переключает ответы по проекту на формулировки сервера.
Сервер по умолчанию слушает порт 8000. Если он занят, задайте
`SYNONYX_API_PORT` для сервера и соответствующий `SYNONYX_API_TARGET` для Vite.

Для прогона открытых сценариев запустите из корня проекта
`python scripts/audit_integration.py` с переменной `SYNONYX_CASE_ZIP`.
Скрипт использует интерфейсный прокси на порту 5173. Для другого адреса
задайте `SYNONYX_TEST_URL`. Результаты лежат в `sessions/audit_results.json`,
журналы модельных вызовов сохраняются в `sessions/`.

Результаты последней проверки, ограничения и материалы для защиты собраны в [отчёте по сценариям](AUDIT.md).

## Редактирование схемы

В разделе «Схема» можно менять оформление и расположение объектов в редакторе draw.io. Сохранённые правки относятся к текущей сессии и конфигурации. Они видны в режиме «Просмотр» и входят в скачиваемый файл `.drawio`. Кнопка «Сбросить» возвращает схему по расчёту.

Колесо мыши масштабирует схему вокруг курсора, перетаскивание перемещает её внутри области просмотра. Кнопка «Показать целиком» возвращает масштаб и положение к исходному виду.

Расчёт правил и служебный JSON формируются по данным из чата. Чтобы изменить правила обмена, уточните параметры в чате.

Если `embed.diagrams.net` недоступен, просмотр показывает схему по расчёту, а скачивание использует последний сохранённый XML. Для собственного редактора укажите `VITE_DRAWIO_EMBED_URL` в настройках фронтенда.

## Локальные ключи Groq

Для трёх ключей создайте в корне локальный файл `.env.groq`.

```dotenv
GROQ_ACTIVE_SLOT=1
GROQ_API_KEY_1=
GROQ_API_KEY_2=
GROQ_API_KEY_3=
```

Вставьте ключи в заполненные слоты и перезапустите API, чтобы загрузить настройки. При HTTP 429 клиент автоматически повторит тот же запрос со следующим доступным ключом. Срок ожидания хранится отдельно для каждого ключа. Если лимит исчерпан у всех, чат показывает время до следующей попытки. Несколько ключей одной организации могут исчерпать общую квоту одновременно. [Лимиты Groq](https://console.groq.com/docs/rate-limits)
